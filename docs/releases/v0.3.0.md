# 司南 Nanpad 0.3.0

本版补充网站注册账号管理、凭据位置查询、实时邮箱数量检查和可选邮件提醒，让站点账号、注册邮箱和后续检查可以在同一个桌面应用里维护。

## 网站账号

- 「密钥」类型选择增加「网站账号 / 密码」，显示登录地址、用户名和密码字段。
- 智能粘贴识别网站网址，按主机名填写名称，将登录地址保存到加密账号字段，清除网址中的嵌入凭据、查询参数和片段。
- 保存后通过现有双向资产关系关联注册邮箱；解锁后在详情查看登录信息。
- 取消解锁或凭据保存失败时保留表单，不再写入资产并提示成功。

登录信息保存在主密码库，JSON 资产导出不包含这些凭据。普通名称、提示、标签和说明仍为资产元信息。浏览器插件快速保存属于后续计划，本版不含插件。

## Agent 与邮箱

- 凭据定位只返回本机资产详情入口，点击「打开凭据位置」后由用户解锁查看；模型不读取或确认密码存在。
- 网页登录关联的 AI 订阅会提示前往授权详情管理，不会定位到不存在的普通密码面板。
- 邮箱详情支持 IMAP TLS 连接设置和「检查新邮件」，显示总数、未读、新增及检查时间。
- 首次检查或 UID 基线重置时新增未知，不显示成零；手动检查与推送使用独立游标。
- 发送问题前可以开启「本次允许查询邮箱」。许可只对本次问答有效，主进程会独立校验；模型仅接收数量和时间，不读取标题、正文或附件。

问题、近期对话和本地 RAG 命中的资产元信息或文档片段仍会发送给用户配置的真实模型服务。加密库内容不进入模型，并不意味着用户主动输入的所有文字都不会联网。

## 邮件推送

「设置 → 邮件推送」增加 Telegram、Server酱 / 微信和企业微信群机器人。由用户配置自己的渠道凭据及目标，默认关闭。启用后需保持应用运行、密钥库解锁；首次检查仅建立基线，后续新增邮件才触发通知。

通知只包含新增数量、相关邮箱未读数量和检查时间，不含邮箱地址、邮件标题、正文或密码。个人微信通过 Server酱接收，不支持个人微信自动登录。外部渠道超时重试不能保证通知恰好到达一次。

推送检查进度与待发提醒保存在同一次加密提交中。检查完成但保存前锁库、退出或写入失败时，下次仍可从上次成功保存的进度检查。密钥库统一串行化凭据保存、解锁及修改主密码，避免后台推送与用户操作争用临时文件；保存失败不会覆盖内存中的旧记录，锁库会取消旧的排队任务。

## 安装与升级

Windows x64 安装包名为 `Nanpad-0.3.0-setup.exe`，校验值以同一 Release 的 `SHA256SUMS.txt` 为准。当前构建未配置代码签名。升级前备份完整数据目录，保留原有资产、资料和主密码，不需要删除数据重新初始化。

已有邮箱可在详情补充 IMAP TLS 主机和端口，并使用服务商支持的用户名及密码 / 授权码。Google/Microsoft 网页身份授权不等于获得本版 IMAP 密码登录资格。AI 订阅 OAuth 额度依旧受服务商权限和网络限制，0.3.0 不声称解决了真实账号的所有 HTTP 403。
