# 浏览器快速保存

浏览器插件在你主动打开它时读取当前网页的账号表单，核对后发送到本机司南，再由桌面端确认并加密保存；也可以开启「登录时自动采集」，在提交登录表单时自动送达待确认队列。本文对应 0.8.0；扩展采用 Manifest V3，可在 Chrome、Edge 中加载，尚未上架扩展商店。

## 安装

1. 从 [GitHub Releases](https://github.com/Songwo/nanpad/releases) 下载 `Nanpad-0.8.0-setup.exe` 和 `Nanpad-0.8.0-browser-extension.zip`，使用同一版本的桌面端与插件。Windows 安装包未签名，可用同一 Release 的 `SHA256SUMS.txt` 核对文件。
2. 安装并启动司南，完成姓名与主密码设置。将插件 ZIP 解压到一个后续不会删除或移动的目录。
3. Chrome 打开 `chrome://extensions`，Edge 打开 `edge://extensions`，启用开发者模式，点击「加载已解压的扩展程序」，选择包含 `manifest.json` 的目录。
4. 将司南扩展固定到工具栏。插件需要下面的桌面配对才能发送账号密码；默认不开启自动采集，仅加载插件不会记录任何登录。

升级时先更新桌面端，再解压新插件包并在扩展管理页更新加载目录；如果沿用原目录，则替换文件后点击该扩展的重新加载按钮。重新加载插件后重新配对，不要把新文件夹复制进旧扩展目录形成多层嵌套。

### 连接桌面端

1. 打开司南「设置 → 浏览器插件」，点击「生成配对码」，按提示解锁密钥库。
2. 点击配对码旁的复制按钮。在一个普通 HTTP / HTTPS 网站打开插件，将其粘贴进「桌面配对码」，点击「连接」。不要把配对码或主密码填进网站本身的表单。
3. 插件显示「已连接本机司南」后即可发送账号。配对码只用一次，5 分钟后失效；重新生成会替换尚未使用的旧码。
4. 关闭桌面的设置面板，回到资产工作台，便于查看后续待确认账号。

配对保存在当前浏览器会话中。锁库、退出司南、浏览器会话结束或重新加载插件后，需要重新生成配对码。桌面「断开全部插件」会撤销所有连接并清空未处理账号；插件中的「断开」只移除当前浏览器会话保存的连接令牌。

### 采集并保存账号

1. 在网站填好账号、密码，趁表单仍在当前页面时点击插件。插件打开时读取一次，之后可用右上角「重新读取当前页」刷新采集结果；刷新会替换弹窗中的账号和密码。
2. 核对站点地址与网站名称。存在多个候选时，在「选择账号表单」选择正确的一项；账号和密码均可手动修改。密码默认遮挡，可通过眼睛按钮临时显示。
3. 点击「发送到司南」。出现「已送达司南，请在桌面端确认加密保存」只表示接收成功，此时还没有写入密钥库。
4. 回到桌面工作台，在待保存提示中点击「核对账号并保存」。检查网站、登录地址、账号与密码，可选择已经保存的注册邮箱，再点击「添加」。名称、提示、标签和普通说明是明文元信息，不要在这些位置填写密码。
5. 保存后在「密钥」中打开对应网站账号；凭据保存在主密码库，注册邮箱通过关联资产查看。未确认的记录可点击待保存提示右侧的忽略按钮丢弃。

账号待确认队列仅保存在桌面内存中，最多 10 条，每条 5 分钟后过期；锁库、撤销全部连接或退出会清除。点击「核对账号并保存」会领取该记录，取消编辑后不会重新放回队列，需要重新采集。正在编辑其他资产、查看详情或打开设置时，待保存提示会暂时隐藏，不覆盖当前表单。

### 只记录网站

不需要采集密码时，点击「仅记录站点并打开司南」。这项操作无需配对，浏览器可能询问是否允许打开外部应用，选择司南后在桌面点击「填写账号并保存」，再手动补充凭据。

该入口仅传网站名称与站点根地址，不携带账号密码。只记录站点的队列与账号队列独立，最多 10 个不同站点，同一站点去重，退出司南后清空。

### 登录时自动采集

插件弹窗中的「登录时自动采集」开关默认关闭。开启后，在任意网站点击登录、提交含密码的表单时，插件会在提交瞬间读取该表单内的账号与密码，经扩展后台服务发送到司南待确认队列；页面右下角出现「已发送到司南待确认」或失败提示，不打断登录流程，也不会把司南窗口抢到前台。

自动采集使用与手动发送相同的配对、令牌与桌面确认流程：未配对或已锁库时只提示、不发送；到达司南后仍需「核对账号并保存」才会写入密钥库。开关保存在浏览器本机偏好中，重新配对后无需再次开启；关闭开关后内容脚本立即停止监听表单提交。

边界与手动采集一致：只读取提交的那一个表单，验证码 / 一次性代码字段不当作账号或密码；没有 `<form>` 结构的纯脚本登录、iframe、封闭 Shadow DOM、通行密钥及 OAuth 登录不会触发采集；账号为空的表单不发送。频繁提交受每分钟 30 条限制，超出时提示失败，可改用手动采集。

## 工作范围

| 权限 / 组件 | 用途 |
| --- | --- |
| `activeTab` | 用户打开插件后读取当前标签页地址与标题 |
| `scripting` | 在当前标签页的顶层文档执行一次表单读取，包括开放的 Shadow DOM |
| `storage` | 使用 `chrome.storage.session` 保存当前会话的连接令牌，不持久化保存密码；`storage.local` 仅保存自动采集开关这一项偏好 |
| `http://127.0.0.1/*` | 访问本机司南配对与接收服务，实际连接地址固定为 `127.0.0.1:47832` |
| 内容脚本（全站注入） | 仅在开启自动采集后监听密码表单的提交事件，关闭时不读取任何表单 |
| 后台服务（service worker） | 把自动采集的账号转发到本机司南；连接令牌只存在于扩展上下文，不进入网页 |

默认没有常驻表单监听、云端中转、Cookie 读取、浏览历史读取或自动填充；开启自动采集后内容脚本仅在提交含密码表单的瞬间读取该表单。插件不读取浏览器自身的密码库；浏览器已经填入网页可见输入框的值，才可能随当前表单被读到。插件从不接触司南主密码。

采集最多展示 8 个候选，优先识别可见、启用的密码框及同组账号字段，过滤隐藏框和可识别的一次性验证码。网页结构可能让识别不准确，发送前仍需核对。iframe 中的表单、封闭 Shadow DOM、通行密钥、第三方 OAuth 或验证码登录不提供可采集的账号密码；只读到账号时，可手填密码或仅记录站点。网站已跳转、清空或遮蔽表单时，插件不能恢复此前输入的值。

账号密码通过带令牌认证的本机 HTTP POST 发送，`nanpad://` 入口不允许携带密码。所有站点地址都会移除嵌入凭据、路径、查询参数和片段，避免带入 OAuth、密码重置等链接中的令牌；需要完整登录路径时，可在桌面加密账号字段中补充。网站名称来自网页标题，可能带有个人信息，发送前可修改。

本机连接不经云端，但 HTTP 并非 TLS 加密通道，不能防御已控制本机或浏览器的恶意程序。网页本身使用 HTTP 时，它与网站服务器之间的登录通信也不会因插件而得到加密。完整存储和网络边界见 [安全与备份](SECURITY.md#浏览器插件)。

## 排查

- 浏览器内部页面、本地文件和 `javascript:` 地址不支持保存。
- 「无法连接司南」：确认运行的是 0.7.0 或更新版本（自动采集需 0.8.0），桌面已解锁。旧版 0.6.0 不提供账号配对服务；网页预览也不能接收账号。
- 「配对码无效或已过期」：在桌面重新生成，完整复制到插件。不要继续使用已配对过的旧码。
- 「密钥库已锁定」或「连接已失效」：先解锁，再重新配对。解锁不会恢复旧连接或已经清除的队列。
- 桌面提示端口被占用：本机服务使用 `127.0.0.1:47832`，关闭其他司南实例后重新生成配对码。若仍占用，检查使用该端口的本机程序；当前界面没有自定义端口入口，不需要开放路由器端口或公网访问。
- 未识别表单：确认当前页仍保留账号与密码输入框，尝试重新读取。遇到浏览器权限限制或上述不支持的表单结构，手填字段即可。
- 桌面未显示待保存提示：关闭设置、资产详情或当前编辑表单。等待超过 5 分钟、已经锁库或退出时，需要重新发送。
- 发送失败或网络超时：先查看桌面待确认记录，避免重复发送；插件不会自动重试。待确认账号超过 10 条时，先保存或忽略旧记录。
- 只记录站点没有打开窗口：确认已安装或启动司南，并允许浏览器打开外部应用。自编译或移动便携目录后，重新启动该目录下的桌面端以更新系统协议路径，保留原数据目录。
- 已有相同网站账号：可以忽略请求，在已有资产中编辑。插件不会读取密钥库进行查重，也不会自动更新原密码；同一网站可以有多个账号。

## 开发与验证

`npm run extension:build` 将插件、共享链接校验模块和图标复制到 `release/v版本号/nanpad-browser-extension/`。手工加载时选择构建目录，不是源码目录。

构建命令：

```bash
npm run desktop:build
npm run extension:build
```

本机桥接的实现位于 `electron/services/extension-bridge.mjs`，表单采集位于 `browser-extension/form-capture.mjs`。验证结果及本版实际执行范围见 [0.8.0 发布说明](releases/v0.8.0.md)；隔离测试不应读取真人账号或日常浏览器会话。
